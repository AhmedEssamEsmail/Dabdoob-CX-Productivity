## S03-01: fdActivityExport_ — ticket-activities export client
Kind: mini
ID: S03-01
Parent: S03
Owner: data-engineer
Depends: none
Criteria: PLAN #1
Skills: none
Budget: files=2; actions=6; changed_lines=190; minutes=10

### Goal
`fdActivityExport_(dateKey): Promise<Row[]>` — request the export for one day,
poll the returned download URL until ready (cap ~60s), parse
`activities_data`, return raw activity objects. Reuses `fdGet_`/`fdApiKey_`
plumbing; throws `DescribedError missing_credentials` when no key (same
contract as `fetchMaqsamRows`).

### Files
- Edit: `src/features/shared/jobs/freshdesk.ts` | append export section after `fdTicketsPage_` (:195)
- Create: `tests/jobs/fd-activity-export.test.ts` | mocked-fetch tests

### Context
- `Reference_Code.gs:168-269` — the legacy flow verbatim (request →
  `exportData.url || exportData.export[0].url` → sleep → download →
  `activities_data`).
- `freshdesk.ts:52-69` — `fdGet_` pattern (Basic auth, 429 retry).
- The download URL is NOT authed in the legacy (plain GET); keep that but
  still retry 429 via a small internal helper.

### Contract
- Signature: `export async function fdActivityExport_(dateKey: string): Promise<Record<string, unknown>[]>` — `dateKey` is `YYYY-MM-DD` in UTC.
- Poll download URL with `sleep`, up to ~60s total / 10 tries; throw a
  descriptive error when the export never becomes ready.
- Returns `activities_data` (or `[]` when absent — same tolerance as legacy).
- No filtering inside (mapper's job); each element is the raw activity object
  incl. `performed_at`, `ticket_id`, `performer_id`, `performer_type`,
  `activity`.
- Unit tests stub `fetch`: happy path (url on first response), `export[0].url`
  shape, poll-until-ready, empty `activities_data`, missing creds throws.

### Actions
1. Write `fdActivityExport_` + a `fdDownloadUrl_` helper (fetch + 429 retry).
2. Poll loop with deadline.
3. Parse + return `activities_data ?? []`.
4. Write the 5 mocked-fetch tests.
5. tsc + vitest.
6. eslint `freshdesk.ts` + the test file.

### Done when
- `npx tsc --noEmit` clean; `npx vitest run tests/jobs/fd-activity-export.test.ts` green

### Verify
- Run: `npx tsc --noEmit && npx vitest run tests/jobs/fd-activity-export.test.ts` -> exit 0

## S03-02: fdActivityToCells_ — activity → 10-cell mirror row
Kind: mini
ID: S03-02
Parent: S03
Owner: data-engineer
Depends: S03-01
Criteria: PLAN #1
Skills: none
Budget: files=2; actions=6; changed_lines=160; minutes=10

### Goal
`fdActivityToCells_(activity, rosterNames): unknown[] | null` — raw export
activity → the 10-cell mirror layout (cells 0-8 named + trailing `''`),
filtering `performer_type === 'user'`, expanding `new_ticket`/`status` into
the sheet's Activity-Type/Field/New-Value cells, resolving performer names
through the roster fd-directory.

### Files
- Edit: `src/features/shared/jobs/vendor-apis.ts` | append fd-activity section
- Create: `tests/jobs/fd-activity-cells.test.ts` | mapper cases

### Context
- `engine-live.ts:142-144` — the 10-cell layout + which indexes readers use.
- `Reference_Code.gs:236-253` — filter + new_ticket/status expansion;
  `statusMap` ≡ `FD_STATUS_NAMES`.
- `tlqueue.ts:121-136` (`engine-live.ts` roster byId/byName) — roster carries
  `freshdesk_id`/`freshdesk_name`; resolve `performer_id` → name there.
- **RESEARCH (blocking):** confirm whether export activities carry old-value
  and the ticket's group at activity time (cells 7/8). If the export object
  lacks them: `old_value` → `''`; `group_name` → resolve at write time from
  `tickets` (current group — drift noted in PLAN). Record the finding in
  results; if the export shape is unverifiable offline, code defensively
  (`pick`-style, multiple candidate keys) and log unmapped fields once.

### Contract
- Output `[performedAtISO, ticketId, performerName, performerType, activityType, fieldChanged, newValue, oldValue, groupName, '']`.
- `performed_at` parsed via the DD/MM/YYYY-then-ISO rule (same rule as
  `Reference_Code.gs` `parseActivityDate`) → emitted ISO instant.
- `performer_type !== 'user'` → `null` (skipped by caller).
- `performerName`: roster `freshdesk_id` → `freshdesk_name`, else
  `User <id>` (legacy fallback).
- `status` value → `FD_STATUS_NAMES` name; `new_ticket` → field/value cells
  exactly as the sheet wrote them.
- Tests cover: status change, new_ticket, non-user skip, name resolution +
  fallback, DD/MM date parse, missing optional fields.

### Actions
1. Write the DD/MM-first `parseFdActivityDate_` helper (mirror the .gs rules).
2. Write `fdActivityToCells_` with roster-name resolution.
3. Emit ISO instants for cells that are timestamps.
4. Write the 6 test cases (incl. old_value/group fallback path).
5. tsc + vitest.
6. eslint `vendor-apis.ts` + the test file.

### Done when

- results notes the export-payload finding for cells 7/8
