# S01 — CTL desk cleanup

Kind: package
Dispatch: NEVER
Owner: mixed (see leaves)

## Contract

`getQaCtlPage(scope)` gains a `scope: 'mine' | 'all'` parameter (default
`'mine'`, pushed through `P.ctlPage` and `/api/qa/getQaCtlPage`):

- **admin**: always receives all rows (`scope` ignored; 'all' is the only admin scope).
- **TL + 'mine'**: only rows with `tl_email === me` — the `shift_tls` leg of
  `qaCtlVisibleTo_` is dropped for the page (it stays for `qaFindOpenCtls_` submit matching).
- **TL + 'all'**: every team's CTLs, read view. The SLA table (`sla`) is
  intentionally unchanged — a TL always sees only their own SLA line.
- Each returned row gains `canClose: boolean` = `qaCanCloseCtl_(row, user, onShift)`
  (`onShift` = `qaOnShiftNow_()` for TLs, `[]` for admins).
- Open/on_hold rows are restricted server-side to agents in
  `qaActiveEmails_()` (dq_hct emails passing `dqHctActive_`); `null` set fails
  open. Closed-history rows are never filtered. The "N open" chip therefore
  stays consistent with the rendered list.
- The client shows a Mine/All `Seg` in the `QaPage` toolbar for TLs only
  (`!isAdmin`), default 'mine', refetching server-side like audit-queue's
  `actMode`. "Open in the form" renders only when `status==='open' && canClose`.

The migration (S01-01) closes historical open/on_hold CTLs as 'confirmed';
it is data-only and independent of the code leaves.

## S01-01: Migration bulk-closes historical CTLs as confirmed

Kind: mini
ID: S01-01
Parent: S01
Owner: supabase-expert
Depends: none

Skills: none
Budget: files=1; actions=3; changed_lines=80; minutes=10

### Goal
One new timestamped migration that sets every **historical** `qa_ctls` row
still in `('open','on_hold')` to `'confirmed'` with the done-shape the app
writes, idempotent on re-run.

### Files
- Generated: `supabase/migrations/` | one output of `npx supabase migration new close_historical_ctls` (record the real filename before editing)

### Context
- `supabase/migrations/20261105172048_quality.sql:104-132` | qa_ctls columns (text dates; `sla_met` text; `submitted_at` timestamptz)
- `src/features/cx-quality/lib/server.ts:1308-1318` | canonical done-field writes in submitQaCtl (shape to mirror)
- `src/features/shared/migration/mappings/ops-tabs.ts:187-197` | 'CTL & Quality' transform: `ctl_id='hist-<Call ID>'`, sheet 'CTL Date' -> `reminded_date`

### Contract
UPDATE `qa_ctls` WHERE `status IN ('open','on_hold')` AND historical, where
historical = `ctl_id LIKE 'hist-%'` OR `audit_id` matches a `qa_audits` row
with `status='historical'` OR `sample_basis='historical'`. Per matched row:
- `status='confirmed'`, `outcome='acknowledged'`
- `submitted_date = COALESCE(NULLIF(reminded_date,''), NULLIF(opened_date,''), due_date)`
- `submitted_at` = that same date (timestamptz cast; Asia/Riyadh wall clock is fine)
- `sla_met` = `'true'`/`'false'` text for `submitted_date <= due_date` (the app upserts a JS boolean into this text column)
- `closed_by = tl_email`, `updated_by='history closeout'`, `updated_at=now()`
- `coaching_notes = COALESCE(NULLIF(coaching_notes,''), 'Coached before the QA tool.')`
Idempotent: the `status IN ('open','on_hold')` guard makes re-run a no-op.
Out of scope: non-historical rows; `qa_audits` writes; any status outside the
existing vocabulary; RLS/grants; remote writes (auto-apply on merge only).

### Actions
1. `npx supabase migration new close_historical_ctls`; write the single UPDATE (plus a `--` comment header) per the contract.
2. Verify scope with a bounded SELECT of the same WHERE clause if CLI/DB access exists (count historical-open vs total open); otherwise record "not verified locally" in results — do not block on live counts.
3. Sanity: re-run mentally/simulate — second run must update 0 rows.

### Done when
- One new timestamped migration file exists; its UPDATE matches the contract exactly.
- Non-historical open/on_hold rows are provably outside the WHERE clause.
- `done` statuses used are only from {'submitted','confirmed','not_confirmed'} ('confirmed' chosen).

### Verify
- Run: `npx supabase migration list` -> new `close_historical_ctls` file listed, timestamped name.
- Optional if local DB is up — Run: `SELECT count(*) FROM qa_ctls WHERE status IN ('open','on_hold') AND (ctl_id LIKE 'hist-%' OR audit_id IN (SELECT audit_id FROM qa_audits WHERE status='historical' OR sample_basis='historical'));` -> 0 after applying.

### Handoff
Historical CTL noise removed; S01-02's list/filter changes then operate on a
clean open set. Write results/S01-01.md (<=10 lines); TL alone updates TRACKER.md.
