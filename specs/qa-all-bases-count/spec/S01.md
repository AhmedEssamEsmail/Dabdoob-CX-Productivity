# S01: Aggregation rule — count every audit
Kind: package
ID: S01
Dispatch: NEVER

## Goal and contract
Every score, count, chart and table in quality analytics is computed over one
population: all audits with `kind !== 'calibration'` (blank kind counts as
audit), `status !== 'voided'`, and a known score (`qaScoreKnown_`). Every
sample basis counts — random, targeted, request, off-queue, non-ticket,
historical, unknown — non-ticket audits blend into agent/team scores, and
`status = 'disputed'` counts immediately (still surfaced via
`health.pendingDisputes` / `notFinal` and `team.pendingDisputes` as info).
Queue/quota (`doneBy` at analytics.ts ~592-596) keeps its queue-slot meaning.
`bases[]`, `nonTicket[]`, `others[]` keep their shapes but are composition
info, not "excluded" lists. `qaDrill_` needs no code change — it inherits the
rollup change. `qaScoresRange_` loses the `randomScore`/`randomAudits` row
fields (only consumer: quality-scores-page.tsx `ScoreCell`, fixed in S02-03).
