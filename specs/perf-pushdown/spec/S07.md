Kind: package
ID: S07

## Goal and contract
`tphLoadStore_` gains `{ window: 'day'|'trend', refreshLog?: boolean }`: day mode
pins the five `prod_tph_*` reads to `.eq('date', dp)` (or `gte/lte dp`) instead of
the 28-day `gte lo`; config comes from `configAll()` (5-min cache), roster from
`pwDirectory()`, columns are projected, and `refresh_log` loads only when asked.
`trend` (default) preserves today's behaviour. P-16's index ships only if T0 says
`prod_tph_tasks` is big AND lacks a date-leading index.

### Contract
`window: 'day'` -> each `prod_tph_*` read `.gte('date', dp).lte('date', dp)`;
`'trend'` (default) keeps `.gte('date', lo)`. Reads go through `readAllPaged`
(no 5k-20k caps, no truncation). `refreshLog` fetched only when `opts.refreshLog === true`
(default false). `config` via `configAll()`; roster via `pwDirectory()` mapped to the
existing `dir.by` shape (`email,name,tlEmail,role,active` all present in
`DirectoryPerson`). Column projections: derive per-table column lists from what the
TPH readers access (grep the `store.days/cases/touches/callsRows/tasks` consumers in
`lib/tph`); keep `storeErrors` semantics — failed tables still record an error and
yield `[]`. `TphStore` field names unchanged.
Out of scope: route call sites (S07-02), `tphDayCore_`/readers' logic, P-16 index.

### Actions
1. Add `opts` param + `TphStoreOpts` type; thread `window`/`refreshLog` through the 6 reads.
2. Swap config read for `configAll()` and roster read for `pwDirectory()`; keep `dir` shape identical.
3. Project the per-table columns actually consumed (record the list in results).
4. Tests: mocked `db()` asserts day-mode `.gte/.lte dp` on all five `prod_tph_*` tables, no `refresh_log` call unless asked, config served by `configAll` path.
5. Parity: same fixture -> `TphStore` contents identical old-vs-new (trend mode).

### Done when
- tests green; `npx tsc --noEmit` clean
- day mode emits per-table `date = dp` bounds; default call shape unchanged
