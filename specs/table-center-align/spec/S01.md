# S01: CSS foundation — global centering rules + per-app stylesheet reconciliation
Kind: package
ID: S01
Dispatch: NEVER

## Goal and contract
Land the cascade that satisfies PLAN #1/#2/#4/#5:

- Every `thead > tr > th` inside `.cx-table` **and** bare `<table>` elements renders `text-align:center`.
- Every `td` (and `tbody th`) carrying `.cx-num`, `.num`, or `.cx-num-col` renders `text-align:center`.
- `tbody th` row labels (`.cx-rowhead`, `.qa-cov__name`, `.tph-hg :first-child`, `.sch-sticky`, `.cx-groupbreak th`, `th[scope=row]`) keep their existing alignment — never blanket-center `tbody th`.
- Existing centered families (`.cx-agegrid`, `.tph-hg`, `.hm-c`, `.sch-grid-table`, `.qa-cov__*`, `.qa-aw`) stay centered.
- Non-table numerals (`.pw-kv dd`, `.qa-w` inputs, `.trk-num`, `.hm-num .input`, `.dk-*` non-table) are out of scope — do not change.

Winning selectors must reach specificity ≥ (0,2,3) to beat `:root .cx-table :is(th,td)` (0,2,1) and `:root .cx-table thead th` (0,2,2). Recommended forms (verified): `:root :is(.cx-table, table) thead tr th` = 0,2,3 and `:root :is(.cx-table, table) :is(td, tbody th):is(.cx-num, .num, .cx-num-col)` = 0,3,2. Do NOT use `!important` or change layout/spacing/colors.

Non-goals: markup edits (S02), tests (S03), `.pw-kv dd`, input alignment, `display:grid` faux-tables.
