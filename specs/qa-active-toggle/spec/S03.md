## Goal and contract
`getQaQueuePage(auditorEmail, active)` ('active' default; 'all' = unfiltered)
narrows the `qa_queue` input `all` by `agent_email ∈ activeSet` BEFORE the
derived lists are built, so `rows`, `passed`, `requests`, and the quota
`waiting` counts become active-only; then post-filters `quotaWeeks[].rows`
(and therefore `quota`) on `r.email` — quota agents are roster-active
(`qaQuotaAgents_`, unchanged) but only dq_hct-active emails survive.
`failMemory` keys follow the filtered rows automatically; `audits` is NOT
filtered (feeds `mine` + `failMemory` lookups only — both preserved). `act` is
computed in `getQaQueuePage` via the S01-01 helpers and passed into
`qaQueuePageFor_`; `null` = run unfiltered (never empty the page). No page
cache here — direct compute. The page Seg lives in `aside` next to
`qa-queue-status`, kept in component state (no hash param).
Non-goals: no schema/RLS changes; `qaWeekQuota_`/`qaRequestRows_`/`qaFailMemory_`
untouched; deliberate exclusions stay unfiltered — `unmatched` import note, the
admin view-as `auditors` picker, `mine`, and the AccessPanel/SamplingPanel
admin tools (separate endpoints); no other pages; no localStorage/hash.
