# S05: Offqueue audits — date-only `interaction_at`
Kind: package
ID: S05
Dispatch: NEVER

## Goal and contract
Audits of `qa_queue.source = 'offqueue'` items ask for a **date** input and store `'yyyy-MM-dd` (leading-quote text marker) in `qa_audits.interaction_at`; every other queue source keeps the required datetime. The server — never the client — decides which validator applies, keyed off the queue row's `source`, so a hand-crafted submit can't sneak a date-only value into a normal audit. Downstream readers (`qaWhen_` `/^\d{4}-\d{2}-\d{2}/`, `qaScoreDate_`, `qaHasInteraction_`) already accept the date-only prefix.

### Context

- `src/features/cx-quality/lib/server.ts:748-769` | inside `qaTx_`, `q` is the queue row — `q.source === 'offqueue'` is already used at :766 for the audit's `source` field
- `src/features/cx-quality/lib/analytics.ts:151-162` | `qaScoreDate_`/`qaHasInteraction_` regexes match the date prefix — a `'yyyy-MM-dd` value flows through unchanged

### Contract
`export function qaCleanInteractionDate_(v: unknown, nowMs?: number): string` —
- normalise: `s = String(v||'').trim().replace('T',' ').split(' ')[0]` (a stray datetime submitted for an offqueue item degrades to its date — the audit still stores date-only);
- must match `/^\d{4}-\d{2}-\d{2}$/` and round-trip `qeFmt_(d,'yyyy-MM-dd') === s` where `d = new Date(s + 'T00:00:00+03:00')`, else `throw new Error('Enter the interaction date (yyyy-MM-dd).')` / `'The interaction date is not valid (use yyyy-MM-dd).'`;
- same bounds as the datetime variant, applied to the date at Riyadh midnight: `d.getTime() > now + 5*60000` → `'The interaction date is in the future.'`; `d.getTime() < now - 180*864e5` → `'The interaction date is more than 180 days ago.'`;
- returns `"'" + s`.
`submitQaAudit` :756 → `const interactionAt = q.source === 'offqueue' ? qaCleanInteractionDate_(input.interactionAt) : qaCleanInteractionAt_(input.interactionAt)` — decided by the QUEUE ROW, inside the transaction, never by a client flag.
Out of scope: calibration submit (:1565 keeps `qaCleanInteractionAt_`), `qaDeriveBasis_` (off-queue basis already derived from source), the form UI (S05-02).

### Actions
1. Add `qaCleanInteractionDate_` to pure.ts per contract (doc line: "offqueue audits enter only the interaction day").
2. Extend the `qaCleanInteractionAt_` import in server.ts to include the new fn; apply the source switch at :756.
3. Write the test: valid `'2026-11-01'`→`'2026-11-01` (leading quote); `'2026-11-01 14:30'`→same date (degrades); `''`, `'01/11/2026'`, `'2026-13-01'`, future date, and >180-day-old date each throw — pass `nowMs` for determinism.
