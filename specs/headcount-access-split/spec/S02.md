Kind: package
ID: S02

## Goal and contract
`src/features/cx-hub/lib/roster.ts` carries the headcount fields end to end: `dqRosterFromHct_` maps `code`/`gender`/`contactNumber`/`status` into `hr_id`/`gender`/`mobile`/`employment_status`, `dqSyncRoster_` syncs them without erasing manual edits (non-empty sheet values win; a blank sheet cell never clears a manual entry), `getRosterAdmin` returns all new fields plus `titleLevel`, `setPersonV2Fields` accepts the editable headcount fields, and `setPersonOverrides`'s manager-eligibility check accepts title-derived TLs/managers. Both leaves touch the same file — strictly serial.

### Files

### Actions

2. Update the adapter-shape comment at :47-49 to include `code`, `gender`, `contactNumber`.
3. In `dqRosterFromHct_`'s `row` object add the four keys above.
4. In `dqSyncRoster_`, add a module const `const DQ_SYNC_KEEP_MANUAL = ['position', 'hiring_date', 'gender', 'mobile', 'hr_id', 'employment_status']`; in the `fields.forEach` patch loop, skip `patch[f] = row[f]` when `DQ_SYNC_KEEP_MANUAL.indexOf(f) !== -1 && String(row[f] || '') === ''` (blank sheet cell never erases a local/manual value; all other fields keep verbatim overwrite semantics, incl. `source`).
5. Keep the `shown` change-report list as-is (it already surfaces `position`).

## S02-02: getRosterAdmin payload + editable headcount fields + title-aware manager check

Criteria: PLAN #4 (edit in dialog), #5 (manager picklist keys off title)

### Goal
`getRosterAdmin` returns `hiringDate`, `gender`, `mobile`, `hrId`, `employmentStatus`, `titleLevel` per person; `setPersonV2Fields` writes the new editable fields and derives `active` from `employmentStatus`; `setPersonOverrides` accepts a title-TL/manager as a reports-to target even when their access role isn't `tl`/`admin`.

### Files
- Edit: `src/features/cx-hub/lib/roster.ts` | getRosterAdmin map (:485-501), setPersonV2Fields (:525-558), setPersonOverrides mgr check (:429-436), imports (:16-33)

### Context
- `src/features/shared/platform/identity.ts` | exports `dqTitleLevel_(position, role)` → `'agent'|'tl'|'manager'` (S03-01)
- `src/features/cx-hub/lib/roster.ts:525-558` | `setPersonV2Fields` currently writes `based_in_country` + `days_off` only; note the row-lookup fallback at :543-555 — extend BOTH updateRow payloads
- `src/features/cx-hub/lib/roster.ts:429-436` | manager eligibility: `mgr.role !== 'tl' && mgr.role !== 'admin'` throws

### Contract
`setPersonV2Fields(email, fields)` — new optional keys, each written only when the key is PRESENT in `fields` (undefined = unchanged):
`position` (trim, <=120 chars), `hiringDate` (`''` or `/^\d{4}-\d{2}-\d{2}$/` else throw 'Enter the hiring date as yyyy-mm-dd.'), `gender`/`mobile`/`hrId`/`employmentStatus` (trim, <=60 chars). Column map: `position`→`position`, `hiringDate`→`hiring_date`, `gender`→`gender`, `mobile`→`mobile`, `hrId`→`hr_id`, `employmentStatus`→`employment_status`. When `employmentStatus` is provided and non-blank, also write `active = employmentStatus.trim().toLowerCase() === 'current'`. Return value gains the written values.
Out of scope: `setPersonOverrides` role/tl override semantics (unchanged), role CHECK constraint (untouched), UI (S06-02 wires the dialog).

### Actions
1. Import `dqTitleLevel_` in the existing `@/features/shared/platform/identity` import (line :29).
2. `getRosterAdmin` person map += `hiringDate: String(r.hiring_date || '')`, `gender`, `mobile`, `hrId: String(r.hr_id || '')`, `employmentStatus: String(r.employment_status || '')`, `titleLevel: dqTitleLevel_(r.position, String(r.role || ''))`.
3. `setPersonV2Fields`: extend the `fields` type; build the new-columns patch per the contract (validation errors before any write); apply to both `updateRow` calls; return `{ email, basedInCountry, daysOff, position, hiringDate, gender, mobile, hrId, employmentStatus }` echoing effective values.
4. `setPersonOverrides` manager check: eligible when `mgr.role === 'admin' || mgr.role === 'tl' || dqTitleLevel_(mgr.position, String(mgr.role || '')) !== 'agent'` — keep the existing `mgrActive` gate and error message.
5. Keep `wcReset()` calls.

### Done when
- `npx tsc --noEmit` and `npx eslint src/features/cx-hub/lib/roster.ts` clean
- `getRosterAdmin` people rows carry the six new keys including `titleLevel`
- `setPersonV2Fields` with `{position, hiringDate, gender, mobile, hrId, employmentStatus:'Left'}` writes the columns and sets `active: false`; a bad `hiringDate` throws
- `setPersonOverrides` can target a person whose `position` matches a TL title even when `role` is `agent`/`admin` — and still rejects agent-titled, agent-role targets
