# debug report - holform-overlap-sweep - 1

Verdict: ROOT_CAUSE_FOUND

Repro: static CSS proof + new unit audit `tests/css-form-guards.test.ts` -> `npx vitest run tests/css-form-guards.test.ts` => 13 failing site checks, 9 guarded-anchor passes (log: specs/holform-overlap-sweep/logs/guard-test.log, exit=1). Browser-level confirmation per PLAN: bounding-box probe on /people-holidays at 1024/1440px.

Root cause: commit f769940 replaced bounded `minmax(Nrem,…)` form tracks with `repeat(N,minmax(0,1fr))`. `.field`/`.cx-field` carry `min-width:0` (src/app/cx-kit.css:246-253) so the wrapper shrinks with the track, but `.input/.select/.cx-input/.cx-select/.cx-textarea` get only `width:100%` (cx-kit.css:275-291) — `min-inline-size:auto` floors each control at its intrinsic min-content (~10-14rem). The control overflows the shrunken cell and the next cell's opaque control/button paints over it. `.qa-pass` survived the same commit only because of its scoped `:is(input…){min-inline-size:0;max-inline-size:100%}` guard (quality.css:144) — the canonical fix.

Sweep covered: all of `src/app/*.css`, `src/app/styles/*.css`, `src/**/*.tsx` (inline `style={{}}` grid/flex: none found — all layout is class-driven).
