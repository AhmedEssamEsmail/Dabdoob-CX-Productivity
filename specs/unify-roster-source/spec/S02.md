A single migration file whose apply removes all nine dead tables, tolerating
their possible prior absence, and failing loudly (not cascading) if anything
still depends on one.

### Context

- `supabase/migrations/20261106202513_migration_hardening.sql` + `20261106151132_remote_reconcile.sql` | history — the reconcile-era RLS policies die with their tables; do NOT edit these files.
- DECISION Risks: no CASCADE — a still-referenced remote object must fail loudly pre/post merge, never be silently dropped.

### Contract
`DROP TABLE IF EXISTS`, schema-qualified `public.`, exactly these names and no
others — one statement per table:
`dq_hct`, `headcount`, `team_structure`, `schedule`, `days_off`,
`weekly_schedule`, `tls`, `tlp`, `md`.
No `CASCADE`. Header comment records: verified unreferenced 2026-11-16 (PLAN),
and the name-collision caution (`tlp` vs `tlp_*`, `schedule` vs
`one_on_one_schedule`, `days_off` table vs `roster.days_off` column).

Out of scope: remote apply (merge-gated + user approval), rollback SQL
(`dq_hct` recreate = `20261109131140_dq_hct_table.sql` +
`20261112142701_headcount_access_split.sql`; the 8 V1 tables = PITR only), any
other object (functions, policies, views, indexes live-or-dead).

### Actions
1. `npx supabase migration new drop_dead_v1_tables`, then write the nine `DROP TABLE IF EXISTS public.<name>;` statements + header comment.
2. Record the generated filename in `results/S02-01.md`.

### Done when
- Exactly one new timestamped file under `supabase/migrations/`; nine `DROP TABLE IF EXISTS public.<name>;` statements; no `CASCADE`; no other migration file touched.
- Each dropped name appears exactly once; no `tlp_*`/`one_on_one_schedule` name is listed.

### Verify

Docblock header: purpose (pre-merge baseline for unify-roster-source), that it
is read-only on both sides, the run command, and that remote reads run only
