### Contract
Add module-level consts (moved verbatim from `mappings/hct.ts`, names may be
`DQ_HCT_*`):
- columns: `['name','email','position','department','section','manager','status','lwd','hiringDate','fdId','fdName','maqsamName','code','gender','contactNumber']`
- sheetToDb: `{ name:'employee name', manager:'direct repporter', hiringDate:'hiring date', fdId:'fresh desk id', fdName:'freshdesk name', maqsamName:'maqsam name', code:'code', gender:'gender', contactNumber:'contact number' }` — unlisted columns (`email,position,department,section,status,lwd`) resolve to their own lowercase name.
- require: `['email','name']`; dedupe key: `'email'`.
Preserve the DECISIONS facts as comments beside the consts: tab is `Sheet1`
(Sheet2/Sheet3 ignored); `Direct Repporter` is misspelled in the real sheet and
mapped verbatim; row-1 cols U-W hold a side table whose dup headers surface as
`name#2`/`email#2` — never read `#N` keys; `code` = HR id, `contactNumber` = mobile.

New `dqReadHct_` body (same export, same signature):
1. `const { readSheet, SPREADSHEETS } = await import('@/features/shared/migration/engine')`
2. `const rows = await readSheet(SPREADSHEETS.hct, 'Sheet1')` — Sheets/API errors propagate (this replaces the `'Roster master is not connected'` throw; an empty sheet yields `[]` -> the existing `'No HCT rows matched'` error downstream). No `'Sheet 1'` fallback.
3. Project each row: `out[col] = (v === undefined || v === '') ? null : v` where `v = row[sheetToDb[col] || col]` — mapRow's null handling only; deliberately NO JSON/INT/NUM coercion (all 15 cols are text; `position` would NaN-null under the engine's global INT set — the retired backfill script's reason verbatim).
4. Drop rows where `email` or `name` is null/undefined (require parity).
5. Last-wins dedupe on `String(rec.email)` via `Map` (upsertOn parity — the table could never hold duplicate emails).
6. Return `Array.from(map.values())`.

Also update stale comments: file header :8-11 (adapter note — it IS the sheet
reader now), the :51-54 comment above the helpers, the `dqReadHct_` docblock
:242-246, and the `jobRosterSync` GATED-G1 comment :384-390 (the dq_hct gate is
obsolete; note the cron route still does not exist and sync now reads the live
sheet).

Out of scope: `dqRosterFromHct_`, `dqSyncRoster_`, sync write semantics,
`dqHctActive_`/`dqInScope_` exports (unchanged), roster schema, any other file.

### Actions
